Version 2 (to try): zero-copy recording through NVMM surfaces
=============================================================

Why
---
Version 1 (the committed code) makes two extra copies per recorded frame:
  record():   BGRA -> GStreamer buffer       6.2 MB, CPU memcpy (gst_buffer_new_memdup)
  nvvidconv:  GStreamer buffer -> NVMM       6.2 MB, probably CPU
Version 2 removes both: a CUDA kernel writes NV12 straight into the encoder's own input surface,
and that surface goes to nvv4l2h265enc without nvvidconv.

Only worth doing if measurement says so: while recording, check the record() time, the
nvvidconv thread in `top -H`, and `tegrastats`.

Design
------
1. Pool of ~4 NVMM surfaces, created once:
     NvBufSurfaceCreateParams p{};  // gpuId 0, width, height,
     p.colorFormat = NVBUF_COLOR_FORMAT_NV12_709;  // BT.709 limited range (check the enum)
     p.layout = NVBUF_LAYOUT_PITCH;  p.memType = NVBUF_MEM_SURFACE_ARRAY;
     NvBufSurfaceCreate(&surface, 1, &p);
   RAII: unique_ptr with a deleter calling NvBufSurfaceDestroy.

2. Map each surface into CUDA once (EGL interop):
     NvBufSurfaceMapEglImage(surface, 0);
     cuGraphicsEGLRegisterImage(&resource, surface->surfaceList[0].mappedAddr.eglImage,
                                CU_GRAPHICS_MAP_RESOURCE_FLAGS_NONE);
     cuGraphicsResourceGetMappedEglFrame(&frame, resource, 0, 0);
     // frame.frame.pPitch[0] = Y plane, frame.frame.pPitch[1] = interleaved CbCr, frame.pitch
   Teardown in reverse: cuGraphicsUnregisterResource, NvBufSurfaceUnMapEglImage.

3. NV12 kernel (~30 lines): one thread per 2x2 block, reads BGRA (or Bayer directly),
   writes 4 Y + 1 CbCr pair with the surface's row pitch. BT.709 limited-range integer
   coefficients:
     Y  = ((  47R + 157G +  16B + 128) >> 8) + 16
     Cb = (( -26R -  86G + 112B + 128) >> 8) + 128
     Cr = (( 112R - 102G -  10B + 128) >> 8) + 128

4. record(frame): take a free surface (none free -> drop the frame), launch the NV12 kernel on
   frame.stream, cudaStreamSynchronize, wrap the NvBufSurface in a GstBuffer and push it:
     gst_buffer_new_wrapped_full(0, surface, sizeof(NvBufSurface), 0, sizeof(NvBufSurface),
                                 slot, return_slot_to_pool);
   This is how NVIDIA's appsrc samples hand NVMM to their plugins: the buffer's memory
   holds the NvBufSurface struct. Verify on JetPack 6. The destroy-notify runs on a
   GStreamer thread, so returning a slot must be thread-safe (mutex or atomic bitmask).

5. Pipeline (no nvvidconv):
     appsrc name=source is-live=true format=time block=false
       caps=video/x-raw(memory:NVMM),format=NV12,width=W,height=H,framerate=F/1
     ! nvv4l2h265enc bitrate=B ! h265parse ! queue ! matroskamux ! filesink name=sink

6. Shutdown: EOS, wait for it on the bus, set the pipeline to NULL (GStreamer releases every
   buffer, returning all surfaces), then unregister and destroy the surfaces.

Build needs (Jetson)
--------------------
  sudo apt install nvidia-l4t-jetson-multimedia-api   # nvbufsurface.h in
                                                      # /usr/src/jetson_multimedia_api/include
  link: nvbufsurface (/usr/lib/aarch64-linux-gnu/nvidia), EGL, CUDA::cuda_driver

Unverified until run on the Jetson
----------------------------------
- appsrc accepting wrapped NvBufSurface buffers with NVMM caps on JetPack 6.1.
- Which NV12 colour-format enum nvv4l2h265enc expects for BT.709 (NV12_709 vs NV12).
- Whether surfaces must be pitch-aligned beyond what NvBufSurfaceCreate gives.

Fallback ("in between", ~30 lines, no Jetson-specific APIs)
-----------------------------------------------------------
Keep version 1, but convert BGRA -> NV12 on the GPU into a pinned buffer and push NV12 instead
of BGRx (caps format=NV12,colorimetry=bt709). Both copies stay, but each shrinks from 6.2 MB to
2.3 MB (about 60% less data), and nvvidconv no longer does a colour conversion.
